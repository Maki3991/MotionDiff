# MotionDiff 两视频比较应用

这是当前首版的本机浏览器应用。深蹲流程接收各一段完整侧面参考视频和学员视频，用 MediaPipe Pose Landmarker 逐帧导出 JSON，再提取动作阶段、进行通用差异比较，并可由后端 AI 生成证据链接的建议。

当前页面中只有深蹲进入可用分析；`videos/test2` 的站立侧抬腿素材仍作为通用比较回归基线。深蹲两段视频应各包含一次“站立→下蹲→最低位→起身→站立”，使用相近侧面机位并保证一个人完整出镜。

## 启动

在 PowerShell 中执行：

```powershell
Set-Location "D:\Softwares\Programming Projects\xi'an-hackathon\MotionDiff"
& .\.venv-mediapipe\Scripts\python.exe .\app.py
```

浏览器打开 `http://127.0.0.1:8765/#analyze/strength/squat`。在页面选择参考视频和学员视频，然后点击“开始分析”。需要 AI 建议时，先在项目根目录 `.env` 配置并重启服务，详见 [AI_API_SETUP.md](AI_API_SETUP.md)。
请保持 PowerShell 服务窗口运行；不要直接双击 `static/index.html`。该 HTML 引用的是应用服务器提供的 `/static/styles.css`，双击以 `file://` 打开时，样式和分析接口都无法正常加载。

若默认端口已被占用，可用 `--port 8766` 启动，并打开对应地址。

应用要求项目内已有：

- `.venv-mediapipe`：MediaPipe Python 环境；
- `models/mediapipe/pose_landmarker_full.task`：Full 模型文件。

如果需要重新准备环境，参见 [MEDIAPIPE_EXPORT.md](MEDIAPIPE_EXPORT.md)。

## 每次分析的产物

上传默认限制：每个视频最多 60 秒、50 MiB（页面简写为 MB），建议使用 10–20 秒的完整单次动作片段。每次上传两段视频，总请求体上限 101 MiB。浏览器先检查大小和时长；服务端在 MediaPipe 前再次校验，并在提取过程中检查实际时间和帧数。时长无法读取时拒绝；预检不通过会删除该次上传的两个视频。校验时长需要上传完成后读取本地视频，不是根据文件名判断。

同一服务进程只允许一组视频处于上传或处理状态，忙碌时新请求直接返回 503；不会积压任务。当前 DTW 使用完整二维矩阵，因此还有每段 3600 帧、两段帧数乘积不超过 3,240,000 的预算。两段均为 60 秒、30 FPS 可以通过帧数门槛；两段均为 60 FPS 时需缩短到约 30 秒。60 秒准入不保证能够快速完成分析，也不代表能可靠识别一分钟内的多次重复。

每次运行生成在 `analysis/app_runs/<run_id>/`：

```text
input/reference.mp4              参考原视频
input/student.mp4                学员原视频
pose/reference/*_keypoints.json  参考视频逐帧 MediaPipe 数据
pose/student/*_keypoints.json    学员视频逐帧 MediaPipe 数据
report/comparison.json            结构化比较结果
report/comparison.md              可读 Markdown 报告
```

逐帧 JSON 保留原始帧号、时间戳、画面尺寸、33 个带语义名称的 MediaPipe 关键点，以及 `visibility`、`presence` 和可选的世界坐标。比较层再根据双肩中点和双肩距离做归一化。

## 当前比较方法

1. 将每帧的双肩中点作为中心，以双肩距离作为尺度，降低画面平移和人物大小差异的影响。
2. 使用肩、肘、腕、髋、膝、踝的有效关键点做 DTW 时间对齐，允许两段动作速度不同。
3. 计算每个关键点的平均位置差、P90 差异和四段片段进度中的峰值差异，并保存两段视频各自对应的帧号和时间戳。
4. 计算肘、肩、膝和髋的二维投影夹角差。
5. 生成一个**未校准相似度指数**，并列出主要关节及其相对参考视频的位置提示。

深蹲额外在关键点预览下方显示“AI 建议”。后端以 `squat_evidence` 中的五个阶段窗口、角度/位置关系、质量信息和最多四张代表性截图请求外部模型；原视频不会发送。模型返回的建议必须引用已有证据 ID，页面显示零到三条，并标记“待核对”。AI 请求失败、关闭或证据不足时，页面保留完整本地报告并显示原因。

这个指数不是合格线，也不代表安全或专业动作结论。每段视频有效姿态帧低于 50%，或 DTW 路径中至少 4 个成对有效关键点的对齐行低于 50% 时，应用会返回“无法判断”。单个关节的平均位置差达到 0.10 个肩宽才列为主要差异；该临时门槛来自一组已有重复样例，尚未广泛校准。质量门槛只处理关键点数据不足，不是动作是否相同的分类器。二维单目数据依赖相近拍摄方向，不能消除任意机位差异。
